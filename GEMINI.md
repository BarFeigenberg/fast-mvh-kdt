# Research Invariants & Project Mandate

## Project Title
**Fast MVH with K-d Tree Dominance Checking in Multi-Objective Search**

---

### Core Research Invariants

1. **Baseline Immutability**:
   - The repository under `baselines/bridging-mvh-dr/` is strictly a **read-only reference oracle**.
   - Under no circumstances should source files in `baselines/` be modified or repurposed as working code. All modifications, extensions, and new algorithmic implementations belong exclusively in `src/`.

2. **Bit-Identical Solution Soundness**:
   - All Pareto fronts generated by new methods (including KD-tree accelerated heuristic selection and dominance pruning) **must be bit-identical** to the baseline outputs on identical problem instances.
   - Any heuristic selection tie-breaking must strictly adhere to Maya Wohlf's lexicographical order convention ($h_i \in H(s)$ indexed by $i = 1, \dots, |H(s)|$), ensuring identical search trajectories and node expansion sequences.

3. **Compiler Optimization Directives**:
   - All performance benchmarking and search execution must be compiled with `-O2` or `-O3` flags with C++20 standard conformance (`-std=c++20`).
   - Debug assertion overhead must be removed from performance evaluations (`-DNDEBUG`), while memory-sanitizers or assertion builds may be used during testing and validation.

4. **Metrics and Instrumentation Protocol**:
   - Track both macro-level wall-clock execution time and micro-level operation metrics:
     - `cmpchk`: Number of dominance comparisons performed during dominance check queries.
     - `cmpupd`: Number of dominance comparisons performed during set update queries.
     - Node expansions, generations, re-insertions, and fallback rates.

---

### Strict Operational Guardrails

5. **ZERO UNCONFIRMED DELETIONS**:
   - The agent is strictly prohibited from executing file deletions (`rm`, `Remove-Item`, git resets, or directory purges) without explicit confirmation from the user.
   - Always prompt for permission before removing any file or directory.

6. **WORKSPACE HYGIENE & SANDBOX**:
   - Never litter the repository root or source directories with temporary test scripts, dumps, or intermediate logs.
   - All temporary verification scripts, scratch files, and one-off tests must reside strictly within a dedicated `scratchpad/` folder (which is tracked in `.gitignore`).

7. **DETERMINISTIC RESULT LOGGING**:
   - Every benchmark or validation run must store its artifacts in `benchmarks/runs/<YYYY-MM-DD_HHMMSS>/` including:
     1. The exact CLI arguments and Git commit hash.
     2. Pareto front outputs (vector files).
     3. Formatted markdown and CSV metric tables (tracking `cmpchk`, `cmpupd`, wall-clock time, node expansions, and fallback counts).

8. **INTERACTIVE CODE APPROVAL REQUIRED**:
   - The agent is strictly prohibited from writing, modifying, or committing any C++ implementation code in `src/` without explicit user sign-off.
   - For any proposed implementation or code change:
     1. Present a clear theoretical summary explaining the algorithmic rationale.
     2. Display the exact code changes / unified diff directly in the chat.
     3. Detail how it preserves theoretical invariants (admissibility, Pareto optimality, correct tie-breaking).
     4. Wait for explicit user confirmation (e.g., "Approved") before touching any files under `src/`.
